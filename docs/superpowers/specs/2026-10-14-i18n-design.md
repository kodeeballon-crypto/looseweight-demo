# 中英文双语支持 (i18n) 设计方案

- **日期**：2026-10-14
- **状态**：待用户评审
- **相关需求**：添加中英文切换功能（界面、领域文案、AI 生成内容均支持英文，保持中式家常减脂菜系特色）

---

## 1. 目标与范围

### 1.1 核心目标
1. 提供全局中英文一键切换功能（`zh` / `en`）。
2. 保持用户偏好持久化（独立存储于 localStorage `looseweight-lang`，导入/导出用户数据不被覆盖）。
3. 首次访问自动检测浏览器语言：中文环境默认 `zh`，非中文环境默认 `en`。
4. 全界面文案、状态标签、图表、校验提示、Toast、系统弹窗完整本地化。
5. AI 生成内容（饮食周表、单餐替换、周表调整对话、训练周表、教练对话、今日鼓励语、营养结构分析）根据当前语言生成对应英文内容，菜系依然保持中式家常减脂，所有用户可见字段以英文输出。
6. 已有本地数据（历史打卡记录中的鼓励语、已生成的历史周表、已有对话历史）保持生成时的原语言，不自动破坏或翻译，用户可随时重新生成英文版本。

### 1.2 非目标 (YAGNI)
- 不需要多语言路由（如 `/#/en/stats`），依然使用单一 HashRouter。
- 不需要三方重量级库（如 `react-i18next`），避免引入 40KB+ 体积与缺乏编译期字典 key 强类型的弱点。
- 不需要服务端/SSR 支持，纯 SPA。

---

## 2. 架构设计 (方案 A: 轻量原生 TypeScript 字典)

### 2.1 模块结构
```
src/
├── i18n/
│   ├── types.ts          # 语言类型定义与字典键值类型推导
│   ├── zh.ts             # 中文字典（作为基准类型）
│   ├── en.ts             # 英文字典（严格实现 BaseDict 接口，漏键报 TS 编译错误）
│   ├── store.ts          # useLang Zustand store (独立持久化 looseweight-lang)
│   ├── index.ts          # useT() Hook 与 getT() 工具函数
│   └── index.test.ts     # 单元测试：键匹配、变量插值、存储与语言检测
```

### 2.2 语言状态管理 (`src/i18n/store.ts`)
- 独立 Zustand store：
  ```ts
  export type Lang = 'zh' | 'en';

  interface LangState {
    lang: Lang;
    setLang: (lang: Lang) => void;
  }
  ```
- 默认值计算：
  - 优先读取 `localStorage.getItem('looseweight-lang')`。
  - 若无，检测 `navigator.language`（如以 `'zh'` 开头则为 `'zh'`，否则为 `'en'`；在无法访问 navigator 的环境回退到 `'zh'`）。
- 切换时副作用：
  - `document.documentElement.lang = lang`
  - 同步更新网页标题 `document.title = t('app.title')`

### 2.3 字典类型安全机制 (`src/i18n/types.ts` & `zh.ts`, `en.ts`)
- `zh.ts` 作为单一真理源（Single Source of Truth），导出纯对象 `zh`。
- `BaseDict = typeof zh`。
- `en.ts` 声明为 `const en: BaseDict = { ... }`。
  - **核心保障**：若中文字典新增或修改了 key，英文字典未同步，TypeScript 编译直接报错。
- 插值支持：
  - `t(key, params?: Record<string, string | number>)`
  - 模板语法使用 `{param}`，如 `t('stats.trend7d', { n: '-0.8' })` -> `"7-day trend -0.8 kg"`。

### 2.4 工具函数与 Hook
- **React 组件内**：
  ```ts
  const { t, lang, setLang } = useT();
  ```
- **非 React / 领域模型 / Store 内部**：
  ```ts
  import { getT, getLang } from '../i18n';
  const t = getT();
  ```

## 3. 领域模型与静态文案多语言适配

### 3.1 领域常量改造 (`src/domain/calc.ts`, `types.ts`, `lifestyle.ts`, `badges.ts` 等)
将现有的静态单语对象改为基于语言的动态取值或提供映射辅助函数：
1. **餐次名称**：
   - `MEAL_LABELS: Record<Lang, Record<MealKey, string>>`
     - zh: `{ breakfast: '早餐', lunch: '午餐', dinner: '晚餐', snack: '加餐' }`
     - en: `{ breakfast: 'Breakfast', lunch: 'Lunch', dinner: 'Dinner', snack: 'Snack' }`
2. **星期名称**：
   - `WEEKDAY_LABELS: Record<Lang, string[]>`
     - zh: `['周一', '周二', '周三', '周四', '周五', '周六', '周日']`
     - en: `['Mon', 'Tue', 'Wed', 'Thu', 'Fri', 'Sat', 'Sun']`
   - `WEEKDAY_FULL_LABELS: Record<Lang, string[]>`
     - en: `['Monday', 'Tuesday', ...]`
3. **热量状态与评语**：
   - `KCAL_STATUS_LABEL: Record<Lang, Record<KcalStatus, string>>`
     - zh: `{ ok: '达标', slight: '略超', over: '超标' }`
     - en: `{ ok: 'On Track', slight: 'Slightly Over', over: 'Over Limit' }`
4. **BMI 等级与活动量**：
   - `bmiLevel(bmi, lang)` 返回对应语言的标签（偏瘦/Underweight, 正常/Normal, 超重/Overweight, 肥胖/Obese）。
   - `ACTIVITY_LABELS[lang][level]`。
5. **生活节奏选项**：
   - `lifestyleOptions(lang)` 提供中英双语的早餐备餐、外卖频次、晚餐耗时选项。
6. **徽章系统 (`badges.ts`)**：
   - 每枚徽章配置 `title: Record<Lang, string>`、`desc: Record<Lang, string>`。
7. **本地离线鼓励语模版 (`encourage.ts`)**：
   - 补充对应英文鼓励语模版，根据当前语言随机抽取。

## 4. UI 界面与交互

### 4.1 语言切换组件 (`LangSwitch.tsx`)
- 外观：精致的 Segmented pill 切换按钮（`中` / `EN`），带平滑过渡与高亮状态。
- 位置：
  1. **桌面端侧边栏**：放在顶部品牌区右侧或正下方。
  2. **移动端/窄屏**：放置在设置页面顶部作为首个配置卡片，方便在底部导航遮挡侧栏时随时切换。

### 4.2 布局与长文本容纳测试
- 英文单词通常比中文长 1.5 - 2.5 倍，确保以下界面不发生折行错位：
  - 侧栏导航（`nav`）项目
  - 底部移动端 Tabbar
  - 饮食/训练周表的星期表头（`Mon` 代替 `周一`，紧凑度更佳）
  - 指标卡（`MetricCard`）数值与副标题
  - 按钮文字（如 `Generate Week Plan` / `Check-in Today`）

### 4.3 图表 (ECharts)
- `Charts.tsx`、`KcalRing.tsx`、`MacroPie.tsx`、`BurnRing.tsx` 将当前 `lang` 作为依赖传入 `useMemo`。
- 坐标轴（如 `日期` / `Date`、`体重` / `Weight`）、图例与 Tooltip 模板跟随语言刷新。

## 5. AI 生成策略与提示词 (Prompt) 适配

### 5.1 策略原则
- **保持高质量结构**：中文 System Prompt 中的营养学规则、严谨 JSON 范例经过充分验证，不推倒重来。
- **动态语言指令附加**：根据 `getLang()`，在提示词末尾增加明确且强约束的输出语言规则：
  - **英文模式 (`en`)**：
    - `Output language: English.`
    - 所有最终呈现给用户的字段（包括菜名 `name`、食材清单 `items`、周要点 `tips`、教练回复 `reply`、动作名称与动作细节 `exercises[].name` / `detail`、营养分析分析文本 `summary` / `tips`、打卡鼓励语 `text`）**必须使用英文**。
    - **菜系特色保留**：明确告知菜品风格保持中式家常减脂菜（如 "Steamed sea bass with mixed grains"、"Stir-fried chicken breast with broccoli"），食材依然使用普通超市/生鲜常见中式食材。
    - 长度要求调整：鼓励语调整为 60–120 英文单词；记忆提炼每条不超过 10 个英文单词。
  - **解析器容错增强 (`parse.ts`)**：
    - `MEMORY_ITEM_MAX` 从 30 扩充到 60 字符，防止英文较长记忆条目被误截断。

## 6. 测试与验证策略

### 6.1 单元测试 (`npm test`)
1. **i18n 基础测试**：
   - 键完整性：校验 `en.ts` 递归包含 `zh.ts` 中的所有 key，无未定义项。
   - 变量插值：校验 `{param}` 替换正确，丢失参数时优雅降级。
   - 语言切换与持久化逻辑。
2. **领域函数测试**：
   - `calc.test.ts`、`lifestyle.test.ts`、`badges.test.ts`：验证双语输出格式。
3. **AI 提示词测试**：
   - 验证传入 `lang='en'` 时，生成的消息包含英文语言约束与对应单词长度控制。

### 6.2 编译与回归
- 运行 `npm run build`，确保 TypeScript 类型检查 100% 通过。
- 保证现有 146 个单元测试保持通过。
